| Принцип ООП | Где реализован в коде | Как работает и зачем нужен |
| :--- | :--- | :--- |
| **Инкапсуляция** | `DatabaseRepository._connection`, `DatabaseRepository._init_db`, `ForumParser.headers` | Внутреннее соединение с SQLite и структура таблицы скрыты от внешнего потребителя. Вся модификация состояния происходит строго через валидирующие методы. |

## 🧠 Теория тестирования: ответы на ключевые вопросы

### 1. В чём разница между юнит-тестированием и интеграционным тестированием?
* **Юнит-тестирование (модульное):**
  * Проверяет работу **одного изолированного кирпичика** (функции, класса или метода) в полной изоляции от внешнего мира.
  * Все внешние зависимости (сеть, файлы, сторонние базы) отсекаются или подменяются моками.
  * *Пример из работы:* `test_parse_html_with_fixture` — тестирует только работу алгоритма парсинга BS4 на заранее заготовленной строке, без реальных сетевых запросов и без БД.
* **Интеграционное тестирование:**
  * Проверяет, как **несколько компонентов работают вместе**.
  * Выявляет ошибки на стыках интерфейсов, несовместимость форматов данных и контрактов вызова.
  * *Пример из работы:* `test_save_to_db_success` — парсер извлекает структуры данных из HTML, передает их в `DatabaseRepository`, а репозиторий записывает их в SQLite. Проверяется корректность взаимодействия двух модулей.

---

### 2. Что такое Mock, MagicMock и patch?
* **Mock (Заглушка / Объект-шпион):**
  * Искусственный объект из библиотеки `unittest.mock`, который имитирует интерфейс реального объекта.
  * Он перехватывает любые обращения к своим атрибутам и методам, записывает факт вызова, количество вызовов и переданные аргументы (`assert_called_once_with(...)`).
  * Позволяет предотвратить нежелательные побочные эффекты (отправку реальных HTTP-запросов, нагрузку на сервер, зависимость от наличия интернета).
* **Чем `Mock` отличается от `MagicMock`?**
  * `MagicMock` — это расширенная версия `Mock`, в которой «из коробки» преднастроена реализация большинства **магических (dunder) методов** Python (`__enter__`, `__exit__`, `__len__`, `__iter__`, `__getitem__`, `__str__` и т.д.).
  * Если обычному `Mock` вызвать `with mock:` или `len(mock)`, он выбросит ошибку `TypeError`, а `MagicMock` отработает корректно. Именно поэтому для мокирования сетевых ответов и контекстных менеджеров используется `MagicMock`.
* **Что такое `@patch`?**
  * Декоратор (или контекстный менеджер), который временно заменяет указанную функцию или класс в целевом модуле на `MagicMock` на время выполнения одного теста. По завершении теста `@patch` гарантированно возвращает оригинальный объект на место.
* **В чём разница между `return_value` и `side_effect`?**
  * `return_value` — возвращает статическое значение при вызове мока (например, объект ответа со статусом 200).
  * `side_effect` — задаёт динамическое поведение: либо выбрасывает исключение (например, `requests.exceptions.ConnectionError`), либо возвращает разные значения при последовательных вызовах (из генератора или списка).

### 3. Зачем нужна оффлайн-фикстура `forum_mock.html`?
* Сетевые тесты, обращающиеся к реальным сайтам, **нестабильны (flaky tests)**: сайт может упасть, изменить верстку, заблокировать IP по лимиту запросов или потребовать Cloudflare-капчу.
* Локальная HTML-фикстура обеспечивает:
  1. **Детерминированность:** тесты всегда выполняются на одинаковых эталонных входных данных.
  2. **Автономность:** тесты запускаются без доступа к интернету.
  3. **Скорость:** тесты отрабатывают за сотые доли секунды.

## 🌐 Веб-парсинг и HTTP

### 1. Зачем передавать `User-Agent` в заголовках (`headers`)?
По умолчанию библиотека `requests` отправляет заголовок:
`User-Agent: python-requests/2.X.X`.
Большинство веб-серверов и систем защиты (Cloudflare, Nginx, WAF) блокируют такие запросы с кодом `403 Forbidden` или `429 Too Many Requests`. Передача валидного браузерного `User-Agent` маскирует автоматизированный скрипт под обычного пользователя.

### 2. Как BeautifulSoup извлекает данные?
1. В `ForumParser.parse_html` выполняется построение DOM-дерева через парсер `lxml` (с автоматическим фоллбэком на встроенный `html.parser`).
2. Поиск контейнеров постов через CSS-селектор: `soup.select(".post, .forum-post, article.post")`.
3. Извлечение уникального ID: считывание атрибута `data-post-id` (или парсинг `id="post-XXX"` через регулярное выражение).
4. Извлечение автора: `.select_one(".author, .username").get_text(strip=True)`.
5. Извлечение сообщения с разметкой: `.select_one(".post-message").decode_contents().strip()` — метод `decode_contents()` сохраняет внутренние HTML-теги (`<strong>`, `<code>`, `<em>`), в отличие от `get_text()`, который бы их удалил.

## 🗄️ База данных SQLite и валидация

### 1. Схема таблицы `comments`:
```sql
CREATE TABLE IF NOT EXISTS comments (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    message TEXT NOT NULL
);
```

### 2. Безопасность и защита от SQL Injection:
Все SQL-запросы в `DatabaseRepository` используют **параметризованные запросы с плейсхолдерами `?`**:
```python
self._connection.execute("INSERT INTO comments (id, name, message) VALUES (?, ?, ?);", (comment_id, username, message))
```
Значения параметров передаются движку SQLite отдельно от текста запроса, что полностью исключает возможность SQL-инъекций.

### 3. Валидация типов и длины данных:
* `comment_id`: проверка `isinstance(comment_id, int)` с отсечением `bool` (так как в Python `isinstance(True, int) == True`). Проверка положительности (`id > 0`).
* `name`: проверка типа `str`, запрет пустых строк, ограничение `len(name) <= 256`.
* `message`: проверка типа `str`, запрет пустых строк, ограничение `len(message) <= 8096`.
* Дубликаты ID: при попытке вставить существующий `id` SQLite выбрасывает `sqlite3.IntegrityError`, который репозиторий перехватывает и преобразует в явный `ValueError`.

## 🎯 Шпаргалка для идеального ответа на защите

* **Преподаватель:** «Почему в Python нужно писать `not isinstance(comment_id, bool)` перед проверкой `int`?»
  * **Ответ:** «В Python тип `bool` исторически является подклассом `int` (`issubclass(bool, int) is True`). Если передать `True`, проверка `isinstance(True, int)` вернет `True`. Поэтому, чтобы не допустить булевы значения вместо чисел, мы явно проверяем `if isinstance(comment_id, bool): raise TypeError(...)`».

* **Преподаватель:** «Зачем мы используем `:memory:` в тестах БД?»
  * **Ответ:** «Строка `':memory:'` указывает SQLite создать базу данных прямо в оперативной памяти процесса. Это дает максимальную скорость выполнения тестов и гарантирует полную изоляцию — после закрытия соединения база удаляется из памяти, не оставляя мусорных файлов на диске».

* **Преподаватель:** «Что возвращает `save_to_db`?»
  * **Ответ:** «Количество успешно сохраненных в базу данных записей (целое число), при этом метод валидирует типы аргументов и поддерживает флаг игнорирования дубликатов».
